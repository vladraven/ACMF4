# ACMF 4.9.3.1 — audit of commit b015125

Baseline audited: b015125
Parent: 2b344e4

## Critical findings

1. b015125 adds two files that did not exist in 2b344e4:
   - acmf/analysis/ews.py
   - acmf/model/drift.py
   Neither is imported by the existing repository. They are duplicate/parallel implementations and must not become part of the canonical ACMF architecture.

2. acmf/solver/engine.py still hardcodes state dimensions and buffer capacity:
   - state_dim=13
   - buffer_capacity=2000
   - three SID random dimensions
   - zeroed dA/dt
   The solver must derive state dimensions from the supplied state/model contract and must receive forcing derivatives causally.

3. The current DDE interface is mathematically inconsistent with the delay-spectrum implementation.
   compute_full_drift_vector consumes delayed derivatives, while compute_dde_jacobians and delay_spectrum assume F(X(t), X(t-Delta)).
   Consequently A1 is exactly zero for TEST_05's callback. The current FAIL is real and must not be hidden by a fallback.

4. acmf/analysis/delay_spectrum.py contains a false fallback:
   eigvals(A0 + A1) are returned when no delay roots are found.
   That is not a delay spectrum and must be removed.

5. acmf/analysis/bifurcation.py hardcodes the Hopf classification threshold 1e-2 and silently creates default numerical solver configuration.

6. acmf/analysis/equilibria.py hardcodes equilibrium tolerances and uniqueness tolerance.

7. acmf/analysis/jacobian.py hardcodes finite-difference step 1e-6.

8. acmf/model/epistemic.py uses a hardcoded exponential overflow cutoff 100. The logistic burst should use a numerically stable sigmoid implementation instead.

9. acmf/model/metabolism.py and acmf/stochastic/diffusion.py contain hardcoded subsystem dimension 3. The state layout itself is intentionally 13/3 for this model version, but numerical loops should derive the active subsystem count from the model contract where possible.

10. run_validation.py previously embedded the complete model parameter set in source code. The correction pack moves that validation configuration into config/calibrated_parameters.json.

11. acmf/validation/framework.py previously ignored TEST_04, TEST_05, TEST_09, TEST_10 and TEST_20 when computing the final validation level. This allowed the suite to report STOCHASTICALLY_VALIDATED while critical dynamic/decision tests failed. This is corrected.

## Not classified as model hardcode

The following are legitimate validation-protocol fixtures when they live inside TEST files:
- random seeds
- scan ranges
- Monte Carlo sample counts
- synthetic network sizes
- test-specific thresholds

They are experimental protocol parameters, not ACMF structural constants.

## Current known model issue

TEST_05 returning:
    delay_jacobian_is_zero

is not a test bug. It exposes that the current implementation does not provide the state-delay coupling required by the declared retarded-DDE characteristic equation.

Do not force TEST_05 to PASS until the delay representation is made mathematically consistent.
